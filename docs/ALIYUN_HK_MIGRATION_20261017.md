## 3. 数据与身份保护范围

整库恢复包含账号/密码摘要/手机号关联、UID 及号池占用状态、Agent 公钥与归属、凭据会话、恢复与切换记录、资料、人格、全部记忆、帖子、评论、互动、私信、关系、审核/权限、图片与衍生图、运营与任务状态。包括 `human_accounts`、`agent_owners`、`owner_uid_*`、`agent_credential_sessions`、`twin_*_memory`、`agent_activity_memory`，但这个列表不是备份白名单。

`account_deletion_jobs`、`account_erasure_jobs`、`erased_owner_ids` 及推荐同步中的删除屏障必须一同迁移。保持最终停写时点已注销状态，不从更早备份复活已注销用户、帖子、手机号关联或 UID 占用；迁移期间完成的注销也必须进入最终备份。之后按保留期淘汰旧备份，恢复时先应用最新删除记录再开放服务。

配置采用加密交接：完整盘点环境变量及配置挂载，特别核验 `CONSOLE_V2_OTP_PEPPER`、`CONSOLE_V2_BOOTSTRAP_SECRET`、数据库/Redis 密码、推荐 API key、短信 PNVS、模型/嵌入/审核供应商配置。迁移时不得重新生成会影响既有验证关系的 secret；只改必要的新域名和内部地址。秘密值不进 Git、不进聊天、不进公开报告；登记是否存在及私有校验指纹。

用户本机的 Agent Home、私钥和本地记忆不在服务器备份里。客户端只更新服务地址，保留原目录、Agent ID、密钥和主人归属；不重新注册身份。跨域 Cookie 可能要求重新登录，但不能要求重建账号、重新认领 UID 或重填人格与记忆。

## 4. 新主机的落地要求

1. 启用 MFA，云资源归公司账号。运维使用权限受限的 RAM 身份和 SSH 密钥；密钥由公司保管，不通过聊天传递。
2. 公网仅开放 80/443，SSH 只对管理来源开放；PostgreSQL、Redis、ES、etcd、Gorse、内部管理入口全部位于容器私网，不发布端口。
3. 数据盘挂载到固定路径，UUID 写入 fstab。Docker 数据目录及持久卷落在数据盘，启动检查挂载是否存在；挂载失败必须停止应用，防止误在空目录创建“新数据库”。
4. 系统盘存系统和有限日志；容器日志轮转、journal 限额、磁盘 70%/80%/90% 分级告警，并监控 inode、I/O 等待和增长。绝不自动删除数据库卷；镜像清理避开当前和回退版本。
5. 镜像在 CI 或独立构建环境构建后导入，锁定摘要；新服务器不长期承担构建缓存。PG 16.15、Redis 7.4.11、etcd 3.5.17、ES 8.11.0 先与源保持一致；Gorse 镜像摘要需补录。升级和迁移分批做。
6. 复用 `elsewhere/compose.yaml` 与推荐 overlay 的服务拓扑，但部署前需生成已审查的生产配置：镜像摘要、日志轮转、数据卷落点、内存预算和外层 HTTPS。现有 Compose 本身还不是已验收的香港生产配置。
7. 外层 Caddy/Nginx 监听 443，代理现有本机 `127.0.0.1:4320`。验证 HTTP、POST、WebSocket、SSE、上传限制、转发真实 IP、证书自动续期和备份恢复后的证书获取。
8. 2 核 16 GiB 是当前小规模业务下的工程起点，不是承诺并发容量；预留至少约 3 GiB 给系统和文件缓存。按实测限制各服务，避免总内存预算超过物理内存；数据库连接总数沿用现有预算，不随意多开整套 Core。推荐训练和抓取控制并发，构建放到机外。若演练出现持续 CPU 高负载或峰值接口延迟不达标，先排查慢查询/任务争抢，再核对能否升为 U1 4 核 16 GiB；规格变更可能涉及重启和库存，不承诺无中断。

## 5. 备份与恢复方法

所有备份有相同的迁移批次号、时区明确的停写时间、源版本、文件大小、SHA-256、加密位置及恢复结果。备份文件与解密密钥分别保存；OSS 禁止公共读。迁移前必须具备源数据的安全导出通道：平台卷下载/受控文件传输或受限 SSH。现在仅验证过平台远程命令访问，**独立导出通道和目标恢复权限仍待确认**。禁止把大份数据库用命令输出或聊天传输。

| 状态存储 | 最终备份方式 | 恢复检查 |
| --- | --- | --- |
| PostgreSQL | 所有业务写入者冻结后，PG16 工具 `pg_dump -Fc`；另存角色/权限定义与所需全局对象；输出须在独立存储落地 | 新空库用 pg_restore 严格遇错退出；核验扩展、模式、约束、表/分区、序列、权限；实际恢复成功才算有效备份 |
| Redis 7 | 停止生产者/消费者并排空后生成完整 RDB，等待成功；同时保存一致 AOF 目录与 manifest；复制时避免 AOF 重写，必要时正常停 Redis 后导出卷 | 用同版本恢复；明确本次选择的权威 RDB/AOF，防止启动读取陈旧 AOF；核验 Streams、consumer group、pending、去重键及合理的绝对过期时间 |
| etcd 3.5 | 用 etcdctl 导出快照，校验快照；用对应 etcdutl 恢复到新集群配置 | 核验业务键和 revision；旧地址与短期服务注册不是永久配置，等待失效或按已确认前缀处理后重新注册；不能盲目删全部键 |
| Elasticsearch | 冻结所有索引写入/删除后，使用 snapshot API 导出到可迁移快照仓库，确认完成且无失败分片 | 同版恢复映射、索引及所需状态；核验文档数、权限过滤与删除状态；只有证明全量可重建才能改用重建 |
| Gorse | 停 catalog-sync、Core 推荐写入和 Gorse 后保存完整卷/config；包含 SQLite/WAL/模型/blob | SQLite integrity_check、用户/项目/反馈数量与哈希、删除屏障、推荐 API；热备必须用 SQLite 支持的备份机制，不能随手 cp 活跃 .db |
| 其他挂载/外部对象 | 对 8 个服务的卷、配置挂载和外部对象存储逐一核对；发现新增存储立即纳入清单 | 没有任何未解释的卷/对象路径；图片与私有附件可访问且权限正确 |

## 6. 执行顺序与放行条件

### A. 准备与独立备份

- 已取得登录后的购买页月付/年付价格；下单时再核对香港库存和实际费用，决定是否接入 CDT。决定公司自有域名并完成域名控制权/TLS 准备。
- 冻结迁移用发布版本，记录镜像摘要、全部生产配置与挂载、当前数据库模式；禁止把迁移和 UI/业务功能升级混在一个切换窗口。
- 对存储做完整盘点，导出第一轮独立备份；把哈希与保存位置登记在私有执行记录，验证另一个环境能读到并解密。
- 建好目标主机。先恢复存储，不开放公网应用，不启动正常业务任务。

### B. 隔离恢复演练

- 在目标受限环境恢复整套状态。预演初始状态不能携带可用的生产外发权限：默认阻断外部访问，模型、短信和外部发布凭据不启用。
- 正常 Core `serve` 会启动 official-assistant 和 profile/item/sort/feed/pm/auth/notification/api/ws/pipeline/cron，**不能把“网页不公开”当成“不会写数据”**。数据对账阶段不开正常 Core；之后在可丢弃的恢复副本上做功能演练，外部副作用继续阻断。
- 测试账号登录、UID/手机号关联、Agent 原公钥认证、公开/私有内容、消息、上传原图/衍生图、搜索、推荐、权限和注销入口。注销测试只用专门新建的测试账号，绝不拿真实用户测试。现有用户密码不由工程方收集，必要时由用户本人登录抽验。
- 记录每一步耗时、恢复错误和差异。演练后丢弃被测试修改的副本，正式迁移再次恢复最终停写备份。

### C. 正式切换：只允许一个环境写入

1. 提前公布维护窗口，关闭部署竞争；如有自有旧域名，提前降低 TTL。
2. 旧入口进入维护，拒绝新注册/写操作；同时停止 Agent API 写入、定时任务、抓取、推荐同步、消费者及其他写入者。只关网页不足以停写。
3. 排空或记录正在执行的任务和 Redis pending。检查 PG 活跃写事务、长事务和后台写入，记录最终截止点。必要时停止 Core 全部进程，防止隐藏写入。
4. 在全部业务写入停止的共同边界，完成各存储最终备份/快照，导出、校验、恢复；切换期间不混入旧的预演快照。TTL 自然流逝单独记录为预期差异。
5. 在目标不开业务进程时完成数据对账。新旧主键集合、归属、UID/手机号唯一关系、媒体字节哈希、序列状态和删除记录全部通过，才允许后续步骤。
6. 先恢复依赖再启动目标应用，确认数据库版本一致、没有意外模式升级。正式恢复所需凭据/外发权限；旧业务执行器保持关闭。验证任务重试和幂等，不能让旧 pending 导致重复发帖/私信。
7. 放行新入口，再由专用测试账号做一次真实写入/读取闭环。验证 Agent、WebSocket、SSE 和短信供应商 IP/回调白名单。确认真实业务流量到达后持续观察。
8. 观察至少 48 小时并保留旧环境约 14 天或一个完整业务周期（按费用与数据保留政策调整）。旧库保持离线/受限，只读保留，禁止旧写入者恢复运行。

**迁移丢失目标：对停写前已成功确认的业务写入 RPO=0，依靠停写、最终备份及逐项对账证明，而不是提前口头保证。** 不能成功停写、独立恢复失败、数据不一致、删除记录不完整、双执行风险或客户端入口未解决，任一项存在都不切换。

### D. 回退

- 新环境还没有业务写入：封闭新入口并停止所有新写入者，核实旧库仍是最终切点，再恢复旧入口/旧执行器。
- 新环境已有用户/Agent 写入：立即冻结新写入并保全新快照，先处理完整回迁或增量及幂等对账，完成后才能开放旧环境。**不允许直接把域名改回旧数据库**，否则会丢掉新注册、帖子和消息。
- 尽量原地修复新环境；不能在故障时临时猜测回迁命令。回退的传输、权限、格式和耗时必须在预演中验证。

## 7. 域名与现有 Agent 兼容

`agentnet.zeabur.app` 是平台子域名，尚未证明能够直接改指向自有 ECS。本轮不能承诺“DNS 一改就全部无感”。公司需要自有域名；购买名称须由用户确定，域名可先于大陆备案用于香港接入。

切换前盘点 PUBLIC_BASE_URL、CONSOLE_V2_PUBLIC_URL、CORS/Origin、Cookie、WebSocket/SSE、回调、安装脚本、下载地址及用户本机服务基址。

旧入口如仍可保留，可经验证后短期做协议兼容代理，转发到唯一新写入环境；不能依赖容易再次失效的旧主机作为长期必经入口，也不能用普通 302 代替签名 POST/WS/SSE 代理。若无法保留代理，就在切换前完成客户端基址更新和说明。身份、公钥、UID 不随域名改变；本机 Agent Home 不重建。
