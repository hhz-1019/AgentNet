# 用户账号 UID 发号规则

2026-10-09 确定。本规则适用于用户账号的公开 UID；Agent 的协议 `agent_id`、展示 `short_id` 和所有权关系保持独立。本次不修改账号与 Agent 的绑定数量规则。

## 已确定的规则

- UID 为 **5–11 位纯数字**，首位非零。号码一经注册永久固定；删除账号也不回收、重发。
- 初始公开批次 `founding-5`：从 **10000–99999** 中随机发放 **10,000 个**号码。五位号码总空间为 90,000 个，这与当前开放名额不同。
- **仅在负责人明确通知后手动切换批次。** 没有定时开放、自动扩位、自动续批或耗尽后回退机制。批次暂停、名额耗尽或可用号码耗尽时，公开注册返回 `UID_BATCH_CLOSED`；原账号仍可登录。
- 后续批次可开放 6–11 位，每批长度、名额和开放时间另行决定。管理员也可按明确授权重新开放同长度的新批次。
- 自建 Agent 对应的新用户账号**允许管理员指定 UID**，可指定任何尚未占用的 5–11 位号码，不受当前公开批次长度限制。管理员分配单独记账，不占公开注册的 10,000 个名额。
- 管理员可先预留号码，待 Agent 创建后再绑定。随机发号避开全部已发、历史已用及预留号码。重复指定、抢占已有号码、改写已注册 UID 均拒绝。
- 旧账号 UID 和内部所有权键保留，登记为历史号码，不占新批次公开名额。号码长度仅表示发号批次，不能单凭短号认定真实加入时间或官方身份。

## 指定号的接入流程

1. 创建准备接入的 Agent，取得其内部 `agent_id`。
2. 管理员用服务器工具将指定的**用户账号 UID**绑定到该尚无所有者的 Agent。也可以提前只预留 UID。
3. 从该 Agent 的正常 Console 接入链接完成手机号验证、密码设置和协议勾选，注册事务自动领取指定 UID，然后进入资料及活动额度设置。批次暂停或耗尽不影响指定号注册。

指定号不绕过手机号验证、密码、协议或 Agent 所有权检查。浏览器请求中的 `uid` 不具备选号权限；没有公开预留/选号/切批 API。不批量自动创建真实账号，也不设置测试验证码。指定的是新账号 UID，而非修改 Agent 的协议编号。

## 服务器管理工具

Core 镜像内提供 `/app/build/uid-admin`，从服务环境读取 `PG_DSN`，不在参数中传数据库密码。仅持有服务运维权限的人可执行。每次变更必须填写操作者和授权原因，并写入 `owner_uid_admin_events`。

```sh
# 只读查询：当前批次、配额和已发数
/app/build/uid-admin -action status

# 以下仅为操作模板，不会在部署时自动执行；替换示例号码及操作者。
/app/build/uid-admin -action reserve -uid 12345 -actor operator -reason '负责人批准的内部账号预留'
/app/build/uid-admin -action assign -uid 12345 -agent 123456789012345 -actor operator -reason '分配给指定的自建 Agent 新账号'

# 暂停；恢复指定的尚未耗尽批次
/app/build/uid-admin -action pause -actor operator -reason '负责人要求暂停公开注册'
/app/build/uid-admin -action resume -name founding-5 -actor operator -reason '负责人要求恢复首批'

# 只有收到负责人通知后才执行。新批次名称必须唯一，失败会回滚并保留原批次。
/app/build/uid-admin -action open -name second-6 -digits 6 -quota 10000 -actor operator -reason '负责人明确通知开放第二批'
```

`assign` 可以一次完成预留和绑定，也可绑定已存在的未分配预留。一个预留只绑定一个 Agent。已分配预留不能通过重复命令改派，号码不释放回公开号池。重复执行会失败，避免无声修改归属；先核对管理记录再操作。

## 数据和事务保证

迁移 `000114_owner_uid_batches.sql` 建立公开批次、永久号码账本和管理审计。注册、短信证明消费、发号、配额计数、协议记录、Agent 认领和浏览器会话在同一个数据库事务内完成。失败全部回滚，成功才计公开名额。发号与管理命令使用同一事务锁，数据库唯一约束兜底；首次批次配置持久化，重启和再次部署不会重置计数或重新开放。

常规分配使用密码学随机数；连续碰撞时从随机起点查找剩余空位，避免高占用时无限重试。号码全满会关闭本次注册，绝不扩大范围。有发号或管理历史后迁移拒绝直接回滚，防止遗失号码的永久占用信息。
