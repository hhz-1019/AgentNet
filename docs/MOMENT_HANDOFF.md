# 「此刻」界面对接

协作分支：`codex/moment-agent-bubbles`。新增导航入口「此刻」，目前为本地演示，尚未接入真实事项和执行服务。

## 设计思路

- 以人和 Agent 的联系组织信息：一个气泡代表一个 Agent，同一对象的事项聚合在一起；自己的画像、目标、发帖确认放在自己的 Agent 中。
- 大小与靠近中心的程度表达关注优先级，兼顾待确认事项、值得反馈的结果和下一步建议。当前大小、位置为演示预设，真实排序规则待定。
- 首页收敛，不设大标题、统计卡片或多组页签；点开后在居中卡片里展示原因、建议、授权范围和操作，关闭时回到原气泡。
- 区分「确认已保存」「Agent 已执行」「收到结果」，不能把点确认显示成任务已完成。

## 前后端对齐

复用现有 attention 事项与 command 队列。前端按关联 Agent 聚合事项，展示优先级、状态、建议和结果；确认时提交事项 ID、版本、选项与补充条件。后端持久保存决定，校验权限、版本与有效期，生成 `attention_response`；前端根据真实执行回执更新状态。

入口代码：`eigenflux/web/social/crossing.tsx`、`crossing.css`；弹窗的可选气泡动效在 `dialog.tsx`，其他弹窗保持原模式。

## 尚未解决：网页决定如何回到 Codex

网页确认还没有接到 Codex 的执行输入和会话上下文。当前 `client/runtime.mjs` 的轮询仅消费 `human_instruction`，需要补齐 `attention_response` 的领取、上下文组装与执行回执。

建议先复用定时检查：按你提出的约每两小时检查一次（实际周期需核对配置），先读取尚未消费的决定，再抓取网络内容。把「原请求、关联人、选择、附加条件、授权范围、时间」作为本轮输入传给承接任务的 Codex，让它知道这次为什么获准、具体能做什么。执行后回写回执，网页与聊天依据同一记录反馈结果。

仍需明确承接的 Agent、宿主与会话绑定方式；定时检查启动的会话不一定就是用户当前聊天。短期先保留可检索的决定记录，每次执行载入相关上下文；画像或目标等长期记忆，仅按本次授权更新。不能假定网页点击能直接修改某个 Codex 聊天的记忆。

命令领取与回执应避免重复执行；过期或已撤回的决定不继续执行。高优先级事项后续可接唤醒机制，缩短定时检查的等待。这一链路仍是对接方案，本分支未实现。
