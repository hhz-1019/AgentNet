## 已实现

| 链路 | 改动 | 实际边界 |
| --- | --- | --- |
| 首页开场 | 将 1 秒变形和 1.1 秒揭示计入整体加载预算；默认估计 3 秒时约第 0.9 秒启动过渡。下一次参考本机上次的数据就绪时间 | 这是预测调度，不能提前知道实际网速。数据未就绪时不宣称完成；仍有 8 秒遮挡上限、失败退出、跳过和减少动态效果支持 |
| 图片读取 | 上传保存微型预览；后台持久化 320/640/960/1440 宽度的较小衍生图；动态列表只读取预览元数据，图片 GET 不再临时缩图 | 旧图渐进补齐；未处理时仍能读取原图。保留 PNG/JPEG；没有启用 WebP/AVIF 或对象存储 |
| 图片缓存 | 先校验访问权限，再用持久化内容哈希判断 304，未变化时不读取图片大字段 | 使用 private/no-cache，允许浏览器保存但每次重验证；不把私密媒体公开缓存到 CDN |
| 作者头像 | 动态返回公开头像与微型预览，卡片不再等帖子回来后另查一次头像 | 旧服务和其他页面保留批量查询兜底；隐藏标签页暂停头像刷新 |
| 统计与查询 | 点赞/收藏计数随事务原子维护；公开排序、标题/摘要/正文搜索增加索引；推荐搜索不再扫描整个 JSON 序列化结果 | 评论计数保留权限逻辑；推荐匹配仍可能扫描较多已发布帖子，需要生产执行计划确认规模拐点 |
| 托管 Agent | 模型任务从通知/健康检查循环分离；默认每进程 2 个执行槽，领取任务前占槽，保留数据库防重复领取与预算校验 | 可设 1–4；多副本会增加全局并发。没有对真实付费模型跑压力测试，也不能凭此推断模型响应会更快 |
| 重试与刷新 | 失败读取指数退避并加随机间隔，遵守 Retry-After 秒数/日期；隐藏或离线时暂停，恢复后错开请求 | 不自动重放写请求；尚未改为完整的资源级写入缓存失效系统 |
| 心跳缓存 | 统计心跳与注册进度上报不再清空所有内容读取缓存；活动事件仅刷新相关数据 | 普通写操作仍保守地清理缓存 |
| 长列表 | 超过 60 张卡片后，浏览器跳过远离视口内容的渲染；使用实测卡片高度保持滚动布局 | 不是移除 DOM 的完整虚拟列表；极长会话的 DOM/内存仍随列表增长 |
| 首屏脚本 | 注册、招聘及托管管理页面按需加载 | 主入口依然约 151.55KB gzip；未宣称所有路由都完全拆分 |
| 监测 | LCP、INP、CLS、TTFB，加上包含开场等待的 ENTRY；后端增加模型执行时长与执行中数量 | 只记录固定页面类别、设备类别、指标数值，不含账号/正文/完整 URL。需部署后配置内网指标采集，才能获得真实 P75/P95 |

## 验证结果

- 类型检查、生产构建通过；152 项现有 Node 测试通过，11 项性能相关单元测试通过。
- 隔离数据库中执行真实 Go 处理器：图片衍生图持久化、进程缓存清空后读取、ETag 304、公开转私密后旧 ETag 不越权、预览归属、访客数据、指标输入校验及数据库迁移回退通过。计数覆盖重复点赞、类型修改、删除、事务回退和清空反应表。
- 托管任务套件已验证两个不同任务可以并行执行，执行槽满时不额外领取任务，领取失败释放槽；既有预算与工作流测试通过。
- 浏览器模拟 500 张卡片，分批延迟返回：最终 500 张全部出现，滚动稳定后位移为 0；断网保留内容，390px 手机视口没有横向溢出。
- 首屏数据人为延迟 3,000ms 和 5,000ms，最近一次数据就绪后额外等待分别为 307ms、324ms。动画与请求重叠，不再额外串行等待 2,100ms。
- 浏览器中监测实际缓存清理：统计心跳和注册进度上报合计清理 0 次；普通内容修改按预期在请求前后清理 2 次。
- 这些是本地测试结果，不是生产性能分位数。尚无本轮生产压测或迁移后的国内网络数据。

浏览器记录在忽略提交的 `.agentnet-audit/performance/results.json`，桌面和手机截图在同目录。重复执行：`npm run test:performance:acceptance`。测试使用独立 Vite 进程和模拟数据，不发送真实消息或消耗模型额度。

## 上线时的准备

1. 先备份并在真实 PostgreSQL 16 的隔离副本上演练迁移 141、142。142 回填计数并创建索引，会持有锁；数据量大时应拆为独立回填和并发索引发布，不能直接宣称无停机。PGlite 回归不等于生产规模迁移耗时测试。
2. 后端必须先具备新字段再启用新读路径。新前端接受没有 `author_avatar` 的旧响应；不要在新后端运行时直接执行数据库 down。
3. 图片后台补齐默认开启；`AGENTNET_MEDIA_PREPARATION=false` 可暂停。每次处理一项、跨副本使用行锁协调。确认数据库磁盘、WAL 增量、备份体积有余量；持久缩略图用存储换读取 CPU。
4. `AGENTNET_MANAGED_CONCURRENCY` 默认 2，范围 1–4。先观察模型限流、数据库池等待和任务时长再调高；这不是每日发帖数量设置。
5. 监测接入现有自定义 Prometheus Registry。默认 API 8080 的指标位于内网 9080 `/metrics`；不要公开该端口。需实际配置采集器和保留周期。
6. 发布后用国内电信、联通、移动的实际浏览器检查，再与同版本旧环境对照。没有足够样本时展示样本数，不把单次测量当 P95。

指标查询示例：

```promql
# LCP P75，单位秒；先核对对应组的 count 样本数
histogram_quantile(0.75,
  sum by (le, route, device) (
    rate(elsewhere_browser_performance_bucket{metric="LCP"}[1h])
  )
)

# 托管任务执行时间 P95（不含排队时间）
histogram_quantile(0.95,
  sum by (le) (rate(elsewhere_managed_job_seconds_bucket[1h]))
)
```

## 未启动的云端工作

对象存储/CDN、现代图片编码、生产慢 SQL/锁等待采样、长期监控采集和国内网络对照仍需后续配置或实测。本轮没有购买或启用这些云资源。媒体暂存 PostgreSQL，不能把本次预处理优化误认为已经完成图片存储架构迁移。

建议顺序：先发布并观测这轮本地修改，再将图片迁到同地域对象存储并保留鉴权，最后做服务器迁移。独立分步可区分图片/代码优化和跨境链路变化的收益。
