# elsewhere 境内部署与性能优化方案

调研日期：2026-10-15。预算按人民币 1,000–2,000 元/月基础设施费用理解；目前没有自有域名和 ICP 备案。本文是方案与采购规格，不代表已购买、迁移、上线或取得生产性能结果。

执行约束更新：用户随后要求先做底层优化并发布到现有Zeabur，保留全部前端展示和开场动画。本文中的缩短开场、页面懒加载、改变图片表现等提案不属于本轮发布范围；服务器、域名备案、OSS/CDN采购仍暂缓。实际发布和验证以 VERIFICATION.md 为准。

## 1. 决策

正式长期环境优先采用**自有阿里云上海 ECS、4 vCPU / 16 GiB、同地域完整业务栈、对象存储与静态资源加速、独立备份**。杭州是同档候选；地域最终由主要用户所在网络的对照测量决定。目前没有证据需要直接升到 8 核或引入 Kubernetes。

继续使用 Zeabur 也是可行路线：其阿里云上海/杭州 4 核 16GB 轻量服务器有现成目录报价，迁移和运维变化较小。它适合低成本验证，也可在实际负载验收通过后承载早期业务；但峰值带宽、共享算力、磁盘容量及后续连接自有 RDS 的条件，需要与标准 ECS 区别对待。

这次应同时完成三件事：缩短国内用户访问链路；取消不必要的页面和接口等待；建立能够定位慢请求的测量与回归机制。换机本身不会消除重复查询、主线程长任务或模型生成耗时。

### 3.2 推荐采购清单

- 地域：上海优先，杭州备选。北京/深圳只在用户分布及晚高峰测试支持时改选；当前没有实测证明上海全国最优。
- 实例：x86 Linux、4 vCPU/16GiB。维持现有软件大版本，迁移时不同时更换数据库引擎或 CPU 架构。
- 磁盘：系统40GB、数据初始100GB ESSD 类云盘作为询价起点；按“现有数据 + 至少90天增长 + 迁移/重建临时空间”复核。磁盘达到70%预警，80%处理。80GB轻量盘不能未经盘点就认定足够。
- 公网：低流量试运行可选按出网流量计费、50Mbps峰值上限，并配置费用告警；它不保证50Mbps，也不是流量费用封顶。正式业务若要求稳定吞吐，比较固定带宽与CDN后的总价。
- 数据库、Redis、etcd、搜索使用同机容器私网或同地域 VPC；不暴露数据库端口到公网。只把 Web 移到国内而继续跨境查数据库，会保留关键延迟。
- 构建在 CI/独立构建环境完成；不要在承载数据库的生产机上同时进行大规模 Go 编译。容器镜像按版本/摘要固定并提前准备国内可访问的镜像仓库。
- 自有 ECS 可继续接入 Zeabur 管理，或使用现有 Compose + 外层 HTTPS 网关；先验证平台接入条件和管理费用再决定，不为迁移重写全部部署流程。

注意，实例表中的 Gbit/s 内网能力不是购买到的公网带宽。举例：单个2.65MB资源占用3Mbps链路，理想独占传输也约7.1秒，尚未计算协议开销和其他用户。低价1–3Mbps套餐不适合未经优化的当前图片链路。[公网带宽计费说明](https://help.aliyun.com/zh/ecs/public-bandwidth/)

轻量通用型的算力和公网峰值均可能在资源争抢时波动；ECS U1 也存在底层平台差异，不能宣传为绝对无抖动。若对算力一致性有明确要求，再比较官方推荐的专用规格。轻量连接 ECS/RDS 的私网互通有账号和地域条件，Zeabur代购与自有账号之间不能直接套用“同账号互通”。[轻量使用须知](https://help.aliyun.com/zh/simple-application-server/product-overview/usage-notes)、[轻量内网互通](https://help.aliyun.com/zh/simple-application-server/user-guide/manage-service-interconnection/)

成本复核公式：计算与磁盘 + ECS出网 + CDN分发 + OSS存储/请求/回源 + 备份 + 平台/日志。优先实测每次访问新增字节和每日访问量。示例：每次新增下载0.5MB、每天10,000次访问约150GB/月；这是测算情景，不是现有流量。CDN和OSS仍会计费，不能把“上CDN”当成流量免费。

## 4. 域名、备案与正式入口

1. 域名由项目实际运营主体持有并实名认证；若按企业运营，优先使用一致的企业主体材料。
2. 购买满足备案资格的境内云资源，按阿里云当前材料、购买时长和所属省份规则提交。按小时试用资源不应假定具有备案资格。
3. 备案期间可做受限测试、数据恢复演练和性能验证；自有域名正式境内公开服务在手续满足后切换，不把“后补备案”当作可先正式上线的依据。
4. Zeabur提供临时预备案子域名，但要求从Zeabur购买境内服务器、账号完成大陆实名认证、供应商支持；官方定位为开发测试过渡，不建议作为商业正式域名。自行购买ECS再接入Zeabur不应假定享有该功能。

依据：[阿里云备案流程FAQ](https://help.aliyun.com/zh/icp-filing/basic-icp-service/support/for-the-record-process-faq)、[备案准备](https://help.aliyun.com/zh/icp-filing/basic-icp-service/user-guide/overview/)、[Zeabur预备案子域名](https://zeabur.com/docs/zh-CN/networking/pre-icp-subdomain)。这里不承诺审批时长；业务内容涉及的额外要求以实际申报核验为准。

## 5. 工程优化任务

### P0：测量与已修复项的发布准备

建立一张端到端性能表，区分 DNS/TCP/TLS、接口服务时间、数据库/连接池、图片传输、前端主线程、模型任务。普通接口增加 request ID、路由归类、耗时与错误类型；适当返回 `Server-Timing` 的应用/数据库汇总耗时。日志和指标不记录聊天正文、token、手机号或高基数完整URL。

浏览器用 Web Vitals/RUM 记录 LCP、INP、CLS，同时记录自己的“页面主要操作可用”事件；按页面、设备、运营商和发布版本看P75/P95。服务器看请求量、延迟、错误率、饱和度，增加连接池等待、锁等待、磁盘IO、容器限流/重启。低流量时保留样本数，不输出看似稳定的P99。

依据：[MDN Server-Timing](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Server-Timing)、[Google SRE监控指南](https://sre.google/sre-book/monitoring-distributed-systems/)、[Web Vitals](https://web.dev/articles/vitals)。

已经在本地完成、仍未部署的项目：首屏遮挡上限、路由按需加载、哈希静态资源缓存、未读摘要接口、侧栏停止全量记忆翻页、活动刷新不再重复读取登录会话、在途GET复用、评论/群成员索引。保留上一轮功能与权限回归；发布前还要在真实网关验证Caddy响应头，在PostgreSQL验证并发索引迁移。

### P1：首屏、图片与滚动交互

- 首屏展示与非关键图片、可选背景资源分离。首屏关键图尽早发现加载，其余图按视口懒加载；不要统一把全部图片设为高优先级或全部懒加载。
- 上传时生成头像和正文缩略图，按实际显示宽度提供尺寸，用WebP/AVIF与原图比较画质和体积。建议初始预算：头像10–30KB、正文首屏缩略图50–150KB；这些是设计目标，允许有合理例外。
- 2.65MB纸张纹理改为更小的资源或原生效果；优化Canvas点数、初始化和帧循环，页面隐藏时停绘，支持减少动画偏好。先录制Performance确认具体长任务，再决定是否需要OffscreenCanvas等额外机制。
- 列表保留游标分页；只有DOM数量和测量证明滚动受阻时再加虚拟列表。拆分长任务，避免每次SSE全页重算。
- 首屏核心数据并行读取，逐块呈现加载/失败状态；切页或搜索词改变后取消旧请求，防止旧响应覆盖新内容。

依据：[LCP优化指南](https://web.dev/articles/optimize-lcp)、[INP优化指南](https://web.dev/articles/optimize-inp)。

### P1：缓存、对象存储和权限

| 内容 | 推荐策略 | 失效/权限要求 |
| --- | --- | --- |
| 含内容哈希的JS/CSS | `public, max-age=31536000, immutable` | 新版本换URL；发布时保留旧资源，避免旧HTML找不到chunk |
| HTML、release信息 | `no-cache`/重新验证 | 不让入口长期指向旧接口和旧资源；no-cache不等于禁止存储 |
| 登录会话、未读、私信、私人画像 | `private, no-store`或按接口验证的更严格策略 | CDN明确绕过；按身份隔离；不能全站套公共缓存 |
| 公开且不可变的装饰资源 | OSS + CDN + 版本化URL | 不含用户访问权限变化 |
| 用户图片和头像 | 先做缩略图；对象私有存储，鉴权后短期授权访问 | 缓存键包含资源版本；撤回公开、删除和头像更新有失效路径 |

“私有OSS回源鉴权”只保护CDN到OSS这一段，不等于用户有权查看图片。私人内容即使使用签名URL也须约束有效期、转发泄漏与缓存行为。撤回要求立即生效的内容继续经权限网关，不能只依赖长时效URL。公开内容缓存也要处理撤回与删除，先完善失效流程再把用户图片大量迁入CDN。

依据：[MDN Cache-Control](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cache-Control)、[OSS与CDN配置指南](https://help.aliyun.com/zh/oss/user-guide/cdn-acceleration)。

### P1：SQL、连接池和接口读取

1. 采集 `pg_stat_statements`，按总耗时、调用次数、平均耗时和读取块数排序；结合应用请求分位数找Top慢接口。该扩展新增到预加载配置通常需要重启，应安排维护窗口。
2. 对热点SELECT做有超时限制的 `EXPLAIN (ANALYZE, BUFFERS)`；使用有代表性的数据量和参数。ANALYZE会实际执行查询，写语句不得直接在生产探测。
3. 应用评论/群成员索引迁移000134，验证索引有效、查询计划和写入影响；不能仅看到迁移编号就认为并发索引成功。
4. 列表查询改批量关联/预聚合，限制字段和每页数量；红点用摘要，深分页优先稳定游标。对文本包含匹配先评估已使用的`pg_trgm`和相应索引，不预设要替换整个搜索架构。
5. 连接池参数配置化，预算按“所有进程与副本之和”核算，并为迁移/管理保留连接；采集WaitCount/WaitDuration等。不能简单让每个进程都增加到几百连接，也不在无测量时新增连接池代理。
6. API到SQL传播context取消和截止时间；响应结束后不继续无意义查询。普通读取与模型生成使用不同超时预算。

依据：[PostgreSQL统计扩展](https://www.postgresql.org/docs/16/pgstatstatements.html)、[EXPLAIN](https://www.postgresql.org/docs/16/sql-explain.html)、[Go连接池管理](https://go.dev/doc/database/manage-connections)、[Go取消操作](https://go.dev/doc/database/cancel-operations)。

### P1：实时消息、重试和模型任务

- SSE/WS保持增量更新，只刷新受影响的数据。SSE健康时降低兜底轮询频率，断线时恢复轮询；后台标签页暂停非必要读取。
- 验证浏览器到入口HTTP/2、SSE心跳/断线重连与事件补偿。HTTP/1.1的SSE在多标签页下会受到较低连接数限制。网关不得缓存事件流；Caddy对`text/event-stream`已有即时flush行为，不盲目全局设置`flush_interval -1`。
- 读取的临时网络失败做有上限的指数退避与随机抖动；写入只有在幂等键等机制保证安全时才重试，避免重复发消息或创建记录。多层重试只保留明确的一层预算。
- 发消息的“服务端已持久化”“对端收到”“Agent开始处理”“生成完成”分开记录和呈现。界面可立即显示发送中，但不能在持久化前宣称成功。
- 托管模型任务采用持久任务ID、受限并发、队列等待指标、可查询状态；适合流式的输出使用流式呈现。保留授权流程。模型慢时不要阻塞普通动态、消息列表和登录。
- 从目标境内服务器逐项验证模型、embedding、安全审核、短信、邮件及Agent回调的可达性和耗时；迁入境内不能保证第三方模型更快。不要在迁移时悄悄换模型或混用不同embedding空间。

依据：[MDN EventSource](https://developer.mozilla.org/en-US/docs/Web/API/EventSource)、[Caddy reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)、[AWS超时与重试指南](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/)。

### P2：运维、备份与后续扩展

当前单机方案存在整机故障中断风险。首先让备份真正能恢复，再讨论多机：每日数据库逻辑备份可作为基础，但仅每日备份最多可能损失一天数据。正式消息服务建议设定并演练RPO≤15分钟、RTO≤60分钟；实现需持续WAL归档+基础备份或合适的托管数据库备份能力，不是给`pg_dump`额外保存WAL就能完成。

备份保存到独立存储，采用受限凭据和保留周期；每月执行恢复演练。Redis含任务/流状态时不可按纯缓存丢弃；搜索索引只有确认可从权威数据完整重建后才按可重建处理。磁盘、WAL积压、备份失败、队列最老任务、错误率和连接池等待都要告警。[PostgreSQL备份](https://www.postgresql.org/docs/16/app-pgdump.html)、[PITR](https://www.postgresql.org/docs/16/continuous-archiving.html)

扩展触发依据：负载下持续CPU/内存或IO饱和、请求P95超标、池等待上升、恢复目标无法满足。优先按瓶颈升级/拆分数据库或模型worker。引入第二个Core副本前必须处理定时任务、消费者、官方助手和工作租约的单次执行，不能把单机多进程容器直接乘二。

## 6. 迁移步骤与回滚

1. **冻结可复现版本。** 整合协作者改动、完成测试，保存Web/Core镜像摘要及迁移版本。此次工作未提交或部署。将代码优化和迁移分别验证，避免无法归因。
2. **盘点。** 列出PG数据库/扩展（仓库已用`pg_trgm`）、Redis持久状态、搜索索引、etcd配置、上传文件、密钥、域名及Agent客户端地址。记录数据大小、增长和完整备份耗时，不输出密钥到报告。
3. **搭建目标。** 同地域部署全栈；准备国内可拉取的镜像与依赖。现有Compose的Web只绑定`127.0.0.1:4320`，Caddy内层关闭自动HTTPS，故自有ECS必须补外层TLS入口与证书续期，不能照搬后把8080直接当正式入口。
4. **隔离恢复演练。** 在限制访问、禁用外发与后台自动任务的目标环境恢复副本。避免复制配置后官方助手、cron和消费者在两边同时运行。验证身份、认领、私信/群、图片权限、搜索和模型依赖；获得恢复耗时后才能安排正式停写窗口。
5. **正式切换前置门槛。** 域名/备案与TLS准备完成，付款配置符合预算，数据恢复及性能验收通过。发布兼容旧Web的Core及索引，再发布调用新接口的Web。
6. **停写并最终同步。** 旧站进入维护/只读，停止所有写入者，包括API、后台任务、Agent回调与消费者；等在途事务/任务处理完毕，执行最终一致性备份与同步。多存储之间的状态需要共同停写边界。
7. **开放唯一新写入点。** 校验关键表数量、消息ID与序列、附件样本、任务状态后切换入口；更新`PUBLIC_BASE_URL`、`CONSOLE_V2_PUBLIC_URL`、回调/允许来源、安装配置和Agent客户端地址。新域名Cookie不会自动继承，按需重新登录。保留原身份和密钥，不要求用户重新注册或重新认领。
8. **旧入口兼容。** 当前使用平台子域名，不能假设拥有其DNS或可以把它任意解析到ECS。验证Zeabur是否允许重绑；否则旧Web提示迁移，API制定受控代理/客户端升级过渡。不能用简单302假定POST、签名、SSE和WS均兼容。自有域名可提前降低TTL，但所有客户端不会同时切换。
9. **观察与回滚。** 留存旧环境与不可变备份，建议观察7天后再决定退役。新端未接收写入时可恢复旧入口；新端已有写入时必须先停写并回迁/对账新增数据，不能直接把DNS拨回旧数据库。应用回滚与数据回滚分别设计，避免破坏性down迁移。

Zeabur官方支持“复制项目+数据同步”，但域名需重绑，有持久卷时也不承诺零停机。即使使用一键复制，仍执行上述一致性和防双写步骤。[Zeabur迁移指南](https://zeabur.com/docs/zh-CN/deploy/manage/migrate-project)

## 7. 验收标准与工作顺序

以下为拟定目标，**不是当前达标结果或服务承诺**。普通页面与模型生成分开考核。

| 项目 | 初始目标 | 测法 |
| --- | --- | --- |
| 首屏体验 | LCP P75≤2.5秒；INP P75≤200ms；CLS P75≤0.1 | 真实用户数据按桌面/手机分组；样本不足时标明，以实验室结果定位但不冒充RUM |
| 页面主要操作可用 | 常规国内网络P75≤2秒、P95≤3秒 | 自定义事件测量；不是用取消遮罩替代内容真正可用 |
| 普通读接口 | 服务端P95≤300ms，国内客户端完整请求P95≤800ms | 不含模型生成、大文件下载；冷/热缓存分别记录 |
| 消息发送 | 持久化确认P95≤800ms；在线接收方收到事件P95≤1秒 | 两个授权测试账号、私信和群分别测；Agent回复另测 |
| 搜索 | 常用查询P95≤1秒 | 覆盖结果多/少/空与权限过滤；以代表性数据集测试 |
| 稳定性 | 目标负载下非预期5xx/网络失败<0.5%，无持续队列增长 | 30分钟稳定负载与短时突发，区分预期4xx/限流 |
| 数据恢复 | 拟定RPO≤15分钟、RTO≤60分钟 | 实际恢复演练；未实现持续备份前不宣称满足 |

Web Vitals阈值来自[官方定义](https://web.dev/articles/vitals)；其余为本项目建议目标。

测试覆盖国内电信、联通、移动及手机网络，至少华东/华北/华南代表性节点，包含晚高峰。记录DNS、TCP、TLS、首字节、传输、主线程；用相同版本/同等数据分别访问旧区和新区，再比较优化版本。每个组合先采30次导航作为工程筛查，不能把少量样本当长期全国SLA。

压测只在隔离测试环境运行，禁止真实短信、外发消息和付费模型调用。未知现有峰值时先做10/25/50/100个活跃虚拟用户的阶梯探索，报告实际RPS、思考时间、SSE连接数和失败率；用户数不等于并发请求数，也不能据此直接宣称能承载多少DAU。正式容量至少覆盖测得实际峰值的2倍并验证剩余资源。

建议执行顺序及工程量估计（非交付承诺，备案等待另计）：

| 阶段 | 内容 | 出口条件 | 估计 |
| --- | --- | --- | --- |
| 第一阶段 | 整理已修复项、接入基础计时、确定采购与域名主体 | 有可复现基线、可审查发布包和结算配置 | 1–2个工程日 |
| 第二阶段 | 目标环境、镜像、HTTPS、备份与恢复演练 | 全栈可运行、能恢复、外部依赖可达 | 1–3个工程日，资源到位后 |
| 第三阶段 | 缩略图/权限缓存、Canvas、热点SQL与连接池 | 场景性能和权限回归通过 | 3–5个工程日，部分可与第二阶段并行 |
| 第四阶段 | 多网络验证、正式切换、持续观察 | 数据一致、主要操作达标、无双写和异常外发 | 切换时长由演练确定，之后观察7天 |

本轮仅形成研究和方案文档，并读取服务器目录；没有购买服务器、注册域名、变更DNS、修改生产数据、推送或部署。
