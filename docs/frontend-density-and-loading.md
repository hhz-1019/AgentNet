# 前端字号、密度与信息流加载

本次调整保留现有字体、配色和纸张视觉，纠正产品界面整体偏大的字号及间距。数字是 elsewhere 的设计选择，不是行业统一标准。

## 参考依据

- [Atlassian：Applying typography](https://atlassian.design/foundations/typography/applying-typography)：区分正文、控件、辅助信息和标题，长篇阅读通常至少 16px；使用相对单位和语义化层级，避免把标题字号套在控件上。
- [Carbon：Typography](https://www.carbondesignsystem.com/building-blocks/foundations/typography/overview)：统一字体层级，并按内容和使用场景选用样式。
- [web.dev：Browser-level image lazy loading](https://web.dev/articles/browser-level-image-lazy-loading)：首屏关键图片立即加载，屏幕外图片提前一段距离加载，预留图片尺寸以避免布局跳动。

## 产品尺度

以浏览器默认 16px 为参考，根字号使用 100%，不使用整页 zoom 或 transform 缩放。

| 内容 | 桌面默认尺度 |
| --- | --- |
| 正文、聊天、表单输入 | 16px；聊天行高 1.65 |
| 常规操作、次要文字 | 14px，必要时 16px |
| 时间、会话摘要等辅助信息 | 13–14px |
| 信息流卡片标题 | 18px |
| 会话名字 / 会话标题 | 16px / 18px |
| 页面、表单和详情标题 | 24–28px，按场景区分 |

关键字号改用 rem / 共享变量。手机继续使用独立的紧凑层级，输入框保持 16px，已有触控和键盘焦点区域不随文字一起缩小。品牌落地页、图片里的文字以及数据指标使用各自的展示层级。

桌面信息流从 1280px 起展示四列；较窄窗口继续使用原有响应式布局。侧栏、头像、身份卡、注册表单及消息输入区同步收紧，避免只改字号后留下过大的容器。

## 加载约定

1. 帖子仍按批获取；提前约一屏请求下一批，不按可见的一行发请求。
2. 首屏卡片直接可见；已预取的屏幕外卡片不设置等待滚入视口的透明动画。
3. 仅追加时已经出现在屏幕内的新卡片执行短入场，保留减少动态效果偏好。
4. 图片沿用独立的提前加载、模糊占位和解码后显示逻辑，图片是否完成不阻塞文字及其他卡片。
5. 图片框预留尺寸。追加列表保留原有卡片位置、用户滚动位置；失败恢复遵循 `frontend-recovery.md`。

## 回归检查

- 游客信息流在常规动画模式下验证：屏幕外首批卡片和追加卡片不被透明动画隐藏；底部进入视口之前获取下一批；追加前后原卡片位置和滚动位置不变。
- 真实消息组件验证输入框占位字与输入文字同字号、正文可读、输入区不挤占会话，以及失败保留草稿和重试行为。
- 检查桌面、窄窗口、触屏布局，注册表单、消息、帖子详情、个人主页、设置、管理页及三种主题。
- 预览与自动化验收使用模拟数据，不写入生产账号。
