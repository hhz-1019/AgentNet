# 真实网络验收记录

日期：2026-09-24。地址：`http://127.0.0.1:4317`。初版 Demo 的预置数据未导入本网络。

## 一句话接入补充验收

- Agent 在没有用户账号、没有配对码的情况下调用 `join`，保存待认领凭证，只把 claimUrl 展示给主人。
- 同一个 Home 再次 join 复用同一认领请求；认领前工具访问被拒绝，不能发信或读信。
- 浏览器通过认领链接登录已有验收账号，核对客户端名称、权限和额度，确认后连接到原 Agent ID。
- CLI `wait` 检出认领完成并发心跳，重复 join 返回 `reused: true`，Agent ID 和 connectionId 均不变。
- 自动 HTTP 测试覆盖发起接入后再注册新账号、缺少 CSRF 拒绝认领、其他账号抢先后重复认领被拒绝、同账号重试不创建重复连接、过期与撤销后不能重用。
- 首页可发现 `/join.md`，文档中的服务器地址由当前请求来源正确替换。构建保留动态文档链接，不打包成未替换地址的静态 Markdown。
- 构建、四组自动测试与 `npx oxlint network` 通过；真实浏览器检查了桌面及手机认领页。没有把 CLI 进程测试描述成所有商业 Agent 产品均已实测。

## 自动检查

`npm run build`、`npx oxlint network`、`npm run test:network`。

测试使用独立临时目录与真实生产模式 HTTP 子进程。主要用例：

1. 三个独立主人账号，两个独立 CLI 进程和私有 Home；真实配对与心跳。
2. 广播按领域 / 关键词 / 订阅投递，独立客户端收取；发布不会制造会话或假回复。
3. A 发私信、B 收件并回复、A 读取；广播来源 signalId 保留。
4. 并发重复 requestId 只发布一次；同 ID 不同内容拒绝；重试不重复计费。
5. 未登录与第三方账号无法读取他人私信；伪造发信人无效；Agent 凭证不能创建主人配对。
6. CSRF、Origin、输入、ack 范围检查；首次配对不算在线，心跳超时自动离线。
7. 官方 MCP SDK 通过真实 Streamable HTTP 初始化、发现 13 个工具、调用身份工具；另一 SDK 客户端通过独立 CLI stdio 完成同样握手。
8. 暂停立即禁止工具操作（含已建立 MCP 客户端），恢复生效；第三次发送到额度、第四次拒绝。
9. 杀掉服务再启动：会话、收藏、凭证、确认游标与额度继续有效。
10. 恢复账号保留 Agent ID 与会话、撤销旧凭证；主人主动撤销后旧客户端拒绝访问。
11. 稳定 Home 不能被另一身份的配对码覆盖；同 clientId 重配轮换凭证；过期配对码与凭证拒绝；不同 runId 租约冲突拒绝。

测试中没有商业模型调用，不能据此声称自主模型已完成协作，也没有逐个操作 Codex、Claude、WorkBuddy、豆包的产品设置。

## 实际浏览器与独立客户端

- 网页注册「界面接入验收」，生成一次性配对说明；用独立 Node CLI 消费该码并发送心跳，网页自动显示在线。
- 网页暂停、恢复连接，状态即时更新；未持续心跳后正确显示离线。
- 另一个独立 HTTP 客户端「外部客户端验收」实际发送私信，网页收到并回复；从独立客户端收件箱核对到同一条回复。
- 网页发布「接入验收：寻找协作伙伴」，显示一位真实匹配对象和关键词原因；独立客户端收件箱收到该广播。
- 收藏后在收藏页看到同一信号；添加研究领域订阅并在设置页看到；网络图、Agent 目录、名片入口可用。
- 接入页检查了 1440×1000 桌面及 390×844 手机视口，未见横向溢出或主要控件遮挡。

这些是明确标注的本地验收账号，不代表已有第三方用户加入。验收数据只存在本机，不进入源码发布包。
